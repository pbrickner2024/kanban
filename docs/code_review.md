## Critical

### 1. API Key Has No Validation or Fallback Handling
**File**: `backend/app/ai.py`, `.env`
**Description**: The OpenRouter API key is correctly kept out of git via `.gitignore`. However, if `OPENROUTER_API_KEY` is missing from the environment, the app starts successfully and only fails at runtime when the AI endpoint is called, with an opaque error.
**Action**: At startup (in `main.py` or `ai.py` module load), assert the key is present and raise a clear `RuntimeError` if not. Document the required env var in `README` or `.env.example`.

### ~~2. No Backend Authentication~~ — FIXED
Added `backend/app/auth.py`: server-side token generation via `secrets.token_hex(32)`, in-memory token store, `require_auth` FastAPI dependency. All board and AI endpoints now require `Authorization: Bearer <token>`. Added `POST /api/auth/login` and `POST /api/auth/logout`.

### ~~3. Client-Side Token Generation~~ — FIXED
`loginApi` in `frontend/src/lib/api.ts` calls `POST /api/auth/login`. Token is generated by the backend and stored client-side only. Removed `validateCredentials` and `generateAuthToken` from `frontend/src/lib/auth.ts`.

### ~~4. Credentials Hardcoded in Frontend~~ — FIXED
Credential validation moved to the backend (`backend/app/auth.py`). Frontend no longer holds or checks credentials. Login error message changed to generic "Invalid username or password".

## High

### ~~5. Card ID Collision Risk~~ — FIXED
`card_id = f"card-{uuid.uuid4().hex}"` — no collision possible.

### ~~6. Race Condition in Card Move~~ — FIXED
`move_card` now opens its transaction with `BEGIN IMMEDIATE` (explicit `conn.isolation_level = None` + `conn.execute("BEGIN IMMEDIATE")`), serialising concurrent writes.

### ~~7. No Rate Limiting on AI Endpoint~~ — FIXED
Module-level `_ai_last_call` float + 5-second minimum gap enforced in `ai_chat`. Returns 429 on violation. No new dependency needed.

### ~~8. Missing Input Length Validation~~ — FIXED
`max_length` Field constraints added to all input models in `backend/app/models.py`: titles 200, details 10 000, messages 4 000, message list 50.

### ~~9. AI Response Not Validated Against Board State~~ — FIXED
After parsing the AI response, `ai_chat` validates every `column_id` and `card_id` in `kanban_update.operations` against the live board. Returns 422 with the bad ID in the detail if any is unknown.

### ~~10. CORS Configured for Development Only~~ — FIXED
`ALLOWED_ORIGINS` env var (comma-separated, default `http://localhost:3000`). Allowed methods restricted to `GET, POST, PATCH, DELETE`; headers restricted to `Authorization, Content-Type`.

## Medium

### ~~11. No Request Body Size Limit~~ — FIXED
HTTP middleware in `backend/app/main.py` rejects requests with `Content-Length` > 1 MB (returns 413).

### 12. Frontend Auth Token in `localStorage` — XSS Risk
**File**: `frontend/src/lib/auth.ts`
**Description**: Token in `localStorage` is readable by any JavaScript on the page. The token is now server-generated and cryptographically strong, which reduces the risk; but `HttpOnly` cookies would fully eliminate it.
**Action**: Move to server-set `HttpOnly` cookies. Requires adding a cookie-based auth flow on the backend.

### 13. No React Error Boundary
**File**: `frontend/src/components/KanbanBoard.tsx`
**Description**: An unhandled runtime error in any child component crashes the entire app with no recovery path.
**Action**: Wrap `KanbanBoard` and `AiSidebar` in a React `ErrorBoundary` that shows a fallback UI and logs the error.

### 14. Optimistic UI Desync on Move Error
**File**: `frontend/src/components/KanbanBoard.tsx:69`
**Description**: `api.moveCard(...).catch(refetch)` applies the DnD-Kit local state move immediately, and only refetches on failure. If the server rejects the move, there is a brief flash of incorrect state.
**Action**: Either use true optimistic updates with rollback, or hold the local move until the server confirms it.

### 15. TypeScript Strict Mode Disabled
**File**: `frontend/tsconfig.json`
**Description**: `strict` is not enabled, allowing implicit `any`, unchecked nullability, and other classes of type errors to go undetected.
**Action**: Enable `"strict": true`. Fix the resulting errors.

### 16. All State and API Logic in One Component
**File**: `frontend/src/components/KanbanBoard.tsx`
**Description**: Board fetch, optimistic updates, AI message handling, and drag-drop coordination all live in a single 300-line component. This makes it hard to test individual behaviours.
**Action**: Extract board state into a custom hook (`useBoardState`). Separate API calls into `frontend/src/lib/api.ts` (some already there — finish the migration).

### ~~17. Missing Database Indexes on Foreign Keys~~ — FIXED
`CREATE INDEX IF NOT EXISTS idx_columns_board_id` and `idx_cards_column_id` added to `init_db()` in `backend/app/database.py`.

### 18. No Structured Logging
**File**: `backend/app/router.py`, `backend/app/ai.py`
**Description**: No logging of API requests, errors, or mutations. Impossible to debug production issues or audit changes.
**Action**: Add a structured logger (e.g., `python-json-logger`). Log every mutation with timestamp and user ID. Log AI errors with request context.

### 19. No Content Security Policy Headers
**File**: `backend/app/main.py`
**Description**: No CSP headers are set. If user-generated content were ever rendered as HTML, or a dependency were compromised, there is no browser-side mitigation.
**Action**: Set `Content-Security-Policy` headers (at minimum `default-src 'self'`). This can be done in FastAPI middleware or an upstream reverse proxy.

### 20. AI System Prompt Does Not Include Valid IDs
**File**: `backend/app/ai.py:12-34`
**Description**: The system prompt describes the board structure but does not enumerate the current column or card IDs. The model can hallucinate IDs that do not exist. (Issue 9 adds server-side rejection; this would reduce the hallucination rate upstream.)
**Action**: Include the live board's column and card IDs in the system prompt.

## Low

### ~~21. Timestamp-Based Card IDs~~ — FIXED (see issue 5)

### ~~22. Error Message Leaks Valid Credentials~~ — FIXED
Login failure message changed to "Invalid username or password".

### 23. No Database Schema Migrations
**File**: `backend/app/database.py`
**Description**: Schema is defined with `CREATE TABLE IF NOT EXISTS`. Any schema change requires a manual migration or data loss.
**Action**: Introduce Alembic (or a lightweight alternative) so schema changes are versioned and reproducible.

### 24. Unused `time` Import Style
**File**: `backend/app/router.py:7`
**Description**: `import time` used as `time.time()`. Minor — could be `from time import time`.
**Action**: Optional cleanup.

### 25. No End-to-End Test Coverage
**File**: `frontend/src/tests/`
**Description**: Playwright is configured but no E2E test files exist. Core flows (login, create card, drag, AI chat) are untested at the integration level.
**Action**: Write E2E tests covering: login, create/edit/delete card, column drag-drop, AI-triggered board change.

### 26. No HTTPS in Docker Compose
**File**: `docker-compose.yml`
**Description**: The service is exposed on plain HTTP port 8000. Deploying to a non-localhost network transmits auth tokens in cleartext.
**Action**: For any non-local deployment, front the app with an nginx reverse proxy that terminates TLS.
